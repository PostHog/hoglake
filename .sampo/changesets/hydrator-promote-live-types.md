hoglake: patch (Server)
---

A file that is still `pending` when its column is promoted from `int` to `long` or `float` to `double` now hydrates with 8-byte bounds in the promoted type. A file without field ids binds by name to the columns of its begin snapshot and used to take their old types as well; it now takes each column's live type, at any depth, in the same query. A promote that commits while a hydrator sweep is under way also no longer leaves that sweep's 4-byte bounds under the live `long` or `double`: the promote's stats re-encode and the end of each sweep share a per-catalog fence, so the sweep widens bounds it wrote under a type promoted since, or the promote waits for the sweep's commit and widens them itself. A compaction group whose rewrite spans a promote now widens its output's bounds to the live type when it commits. Before, such a file was `provided` with bounds readers decode as 8 bytes and was never revisited. Split out of #723 (#675); the Hoglite hydrator there applies the same binding. The race fixes are PostgreSQL only: Hoglite's hydrator and compaction fence their commits on the table's `schema_version` and leave the file or group for the next run instead.
