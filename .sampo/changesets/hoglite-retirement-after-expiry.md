---
hoglake: patch (Server)
---

Hoglite runs retirement after each successful manual expiry (`POST /v1/catalogs/{catalog}/maintenance/expire`). Before, nothing reached Hoglite retirement, so a dropped table's live file rows were never retired and `DELETE /v1/catalogs/{catalog}` answered 409 `tables_pending_retirement` forever. Retirement records its own `retirement` run in the maintenance ledger; its failure is logged, recorded as a failed `retirement` run, and does not fail the expiry response. The expiry response waits for that retirement, so it starts no batch later than twice the expiry purge budget after the request arrived, and never later than 20 s (the default budget's window), except one batch it owes each run, even under a zero purge budget or after a sweep that used the whole window. A batch that commits no rows, such as one on a table whose files carry another table's deletion vectors, does not pay that debt: the run goes on to the next table, starting none more than 1 s past the window or its own start, so one stuck table cannot take every run's only batch. Its Hoglite calls, backlog count and ledger write end within 3 s of the window, or of its own start if the sweep ran longer; a sweep that ends more than 22 s after the request arrived skips retirement, with a warning and a `retirement` audit event with outcome `skipped_late` but no ledger row, so retirement never ends later than 25 s after arrival, inside pyhoglake's 30 s read timeout; the backlog count ends 0.5 s before that, so a stalled count still leaves the ledger write time to record the run. Under that deadline the Hoglite client sends no attempt with under 50 ms left (a tx sent with a few milliseconds could only time out as outcome-unknown) and starts no 200 ms retry pause that would leave it under 50 ms, so a call the deadline cuts short ends at the deadline rather than a pause after it; a timeout the deadline cut short does not count toward the pool's circuit breaker, while one it did not (a full connect or read timeout, or a refused connection) still does. The next expiry continues any backlog. Hoglite retirement now takes `HOGLAKE_RETIREMENT_QUEUE_CEILING` and `HOGLAKE_RETIREMENT_BATCH` (capped at Hoglite's 1,000-row batch) from configuration; before, it always used its built-in 100,000 and 1,000. Because no interval turns that hand-off off, a server whose `HOGLAKE_BACKENDS_FILE` names a Hoglite backend refuses at boot a `HOGLAKE_RETIREMENT_QUEUE_CEILING` below 1 (retirement would never run) or a `HOGLAKE_RETIREMENT_BATCH` below 1 (every Hoglite expiry would fail).
