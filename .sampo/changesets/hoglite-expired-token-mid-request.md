hoglake: patch (Server)
---

Hoglite: a backend 401 that arrives after one of the request's transactions applied (or may have) now answers 503 `commit_outcome_unknown`, naming that transaction, instead of 401 `invalid_token`. hoglite verifies the forwarded token on every call, so a token that expired partway through a long compaction, cleanup or drop failed the request after earlier transactions had committed, and a client that re-minted its token replayed the request as if nothing ran. When that transaction is known to have applied, the message says the request partly applied and, without an idempotency key, to re-read the catalog's state before a retry, rather than that the outcome is unknown. A 401 that arrives mid-way through a namespace containment scan keeps that answer rather than `containment_unverified`. PostgreSQL checks the token once, when the request starts, so it is unaffected. A 403 stays 403: hoglite answers it only for authority that never covers the call, which a retry cannot change. A 401 before anything applied is unchanged. Partial fix: such an operation still fails partway, and refusing at entry a token too short-lived for it is left for a follow-up (refs #680, does not close it).
