---
hoglake: patch (Server)
---

Hoglite stamps a snapshot's time from the engine's clock inside the tenant transaction (SQLite's `strftime('%Y-%m-%dT%H:%M:%fZ', 'now')`, the stored format byte for byte), clamped to the previous snapshot's time as before, instead of from the hoglake pod's clock when it built the transaction. A replica with a fast clock no longer pins every later snapshot forward, and a commit that queued or retried before landing no longer records a time before it became visible, so `at_timestamp=T` resolves to the snapshot that was head at T, as it does on PostgreSQL (`clock_timestamp()` under the commit lock). Snapshot 0 of a new catalog is stamped the same way, and the expiry sweep's retention cutoff is computed on the same engine clock (`'now', '-<retention> seconds'`), so a pod's clock skew no longer expires snapshots earlier or later than PostgreSQL's `now() - make_interval(...)` would. A retention too large for SQLite's calendar fails the sweep's floor advance (recorded as a failed run, as PostgreSQL's `make_interval` error is) instead of expiring every retained snapshot. Existing tenants need no change: the column's encoding is unchanged. (#672)
