hoglake: patch (Server)
---

A Hoglite backend's 401 for a token hoglake accepted no longer answers 401 `invalid_token`, which made clients re-mint the token and retry into the same refusal. A token whose `exp` has passed answers 401 `token_expired`. A token whose `iat` or `nbf` is more than hoglite's fixed 60 s ahead of hoglake's clock, which hoglake accepts only with `HOGLAKE_AUTH_CLOCK_SKEW_SECONDS` above 60, answers 503 `backend_unavailable` with no challenge and a `Retry-After` of the seconds until hoglite admits it (at most 300), so a client retries the same token; metrics and audit count it as `backend_token_not_yet_valid`, not as an outage. Any other answers 403 `backend_refused_authority` with no `WWW-Authenticate` challenge, because a new token with the same claims is refused again; a client may retry the same token after a delay, since a signing key hoglite has not fetched yet passes with time. The typed scoped reads map hoglite's 401 the same way instead of answering an outage's 503. docs/auth.md lists the rules hoglite applies on top of hoglake's, and the contract vectors carry hoglite's verdict as `backend_expect` on every accepted vector routed to it, with a verifier-only vector for each claim rule under which hoglake accepts a token and hoglite refuses it (#681).
