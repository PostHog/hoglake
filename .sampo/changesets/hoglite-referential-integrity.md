hoglake: minor (Server)

The Hoglite tenant schema declares the referential integrity the PostgreSQL schema declares: every table-scoped row (`table_versions`, `columns`, `partition_specs`, `sort_specs`, `table_layouts`, `table_totals`, `files`, `dvs`) references `tables` with `ON DELETE CASCADE`, `dvs` references `files` and `changes` references `snapshots` with a cascade, `table_versions`, `views` and `tables` reference `namespaces` `DEFERRABLE INITIALLY DEFERRED`, `receipt_ended` cascades from `receipts`, and `schema.sql`'s CHECK constraints are ported (the identifier regexes as their exact GLOB equivalents). hoglite enforces them on every tenant connection, so an orphan row is a refused transaction instead of silent corruption: `createCatalog` refuses to bootstrap a tenant whose connection reads `PRAGMA foreign_keys = 0` (503 `backend_unavailable`), and a `FOREIGN KEY constraint failed` refusal of any later transaction surfaces as a 500 (`HogliteIntegrityViolation`, a store bug), never as a client error. Each DDL and commit transaction now writes its snapshot row before its change rows and a replacement's receipt before its ended count; a receipt purge takes the ended count with it.
