## R2-13. [LOW] (memory) src/storage/hoglake_puffin.cpp:341

**Claim:** The puffin footer blob range check computes raw_offset + raw_length as a signed int64 addition of two untrusted, only lower-bounded footer values, so a hostile/corrupt footer triggers signed-integer-overflow UB inside the very validation meant to reject it.

**Verifier:** CONFIRMED with a corrected consequence. Corrected consequence: on real (wrapping) compilers the negative sum hits NumericCast<idx_t>, whose ThrowNumericCastError throws InternalException (duckdb numeric_utils.hpp:49-52), which ClientContext escalates to database-instance invalidation (client_context.cpp:368-370, 723-726) — so one corrupt DV file poisons the whole DuckDB instance rather than yielding the clean InvalidInputException this validator exists to produce; sanitizer builds trap.
