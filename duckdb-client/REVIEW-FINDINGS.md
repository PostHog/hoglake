## 1. [HIGH] (txn) src/storage/hoglake_delete.cpp:102

**Verifier:** Confirmed end-to-end. hoglake_delete.cpp:99-104 builds each statement's superseding DV solely from the pinned-snapshot PlanScan result (server-known live DV); it never consults the transaction's buffered_deletes. hoglake_transaction.cpp:99-117 AddDeletes blindly concatenates registrations for the same (ns, table), so two DELETE (or UPDATE) statements in one explicit transaction touching the same parquet file produce two DeleteFileRegistrations with the same data_file_id, neither containing the other's positions. No client guard limits write statements per transaction, and test/sql/hoglake_write.test covers multi-statement transactions only for INSERTs. Preconditions (two rows of one parquet file deleted by separate statements in one transaction) are trivially reachable. Severity high stands: a basic multi-statement DML transaction is permanently uncommittable.
